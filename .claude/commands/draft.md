[Phase 0: 수동 절차] 토픽 1건으로 아티클 초안을 만든다: $ARGUMENTS

Phase 2에서 자동화 예정. 현재는 아래 수동 절차를 Claude Code가 단계별로 수행하되,
각 단계 산출물을 파일로 저장하고 다음 단계 진행 전 사용자 확인을 받는다.

② 증거 수집 → content/evidence/{slug}.json
   - claims 테이블에서 주제 관련 claim 검색 (FTS)
   - 강제 조건 확인: 독립 출처 3곳+ / 상반 stance 1건+ / T1·T2 2건+
   - 권장: 이론 claim(evidence_type='theory') 1건+ 포함 — 현상을 이론의 경계 조건과 대조하는 각도 우선 (기획서 3.5)
   - 미충족 시 중단하고 "증거 부족" 보고 (CLAUDE.md 절대 규칙 2)
③ 앵글 설계 → content/angles/{slug}.md
   - 서로 다른 논지 3개, 각각 "반증 조건" 포함 → 사용자가 1개 선택
④ 초안 작성 → content/drafts/{slug}.md
   - 문체·전개는 prompts/article_style.md 를 따른다 (어체·독자 눈높이·도입·소제목·번역투·마무리)
   - 필수 고정 요소: 세 줄 요약 / 제언(주체·기간·확인 신호) / 참고자료
   - **편집 규칙** (2026-09-03 D1 편집 피드백에서 확정 — 위반 시 ④ 재작성)
     · 맨 위 요약의 이름은 **"세 줄 요약"**으로 쓴다 (TL;DR 표기 금지 — 사내 독자 기준)
     · **핵심 수치는 본문에 출처와 조사 성격을 함께 밝힌다.** "McKinsey가 해마다 돌리는
       글로벌 AI 설문의 2026년판", "수백 개 기업을 인터뷰해 온 조시 버신의 분석",
       "협업 데이터를 실제로 들여다보는 Worklytics의 도입 사례 분석"처럼 — 설문인지
       사례 분석인지 개인 견해인지가 드러나야 한다. 표본·조사 성격은 **원문에서 확인해**
       기입하고, 추정으로 채우지 않는다. 새로 들어온 수치는 claims 주석 근거를 먼저 확인한다.
     · **소제목의 첫 문장은 앞 문단을 받는 연결 문장**으로 연다. 새 주제를 불쑥 시작하지 않는다.
     · **소제목은 4개 이하.** 쪼개지 말고 합친다.
     · **제언은 박스 구조("리더가 할 일 / 실무자가 할 일")를 쓰지 않는다.** "우리 조직에
       적용해본다면" 같은 제언형 문단으로 녹이되, 주체·기간과 **확인 가능한 신호**는
       자연문으로 남긴다 (예: "4주쯤 지나 그 시간으로 새로 시작한 일을 이름으로 말할 수
       있다면 통로가 생긴 것이고, 아무도 말하지 못한다면 시간은 이미 흩어진 뒤입니다").
     · **이론을 언급할 때는 배경을 한 줄 붙인다** (언제·어디서·무엇을 관찰한 연구인지).
       이론 카드의 frontmatter·핵심 명제 범위 안에서만 쓰고 각색하지 않는다.
     · **내부 발언은 "우리" 시점의 간접 서술로 쓴다.** 직접 인용부호를 쓸 때에만 발언자를
       명시한다. 어느 쪽이든 발언 귀속과 맥락을 왜곡하지 않는다.
   - 그 사이 내용(관찰된 신호 / 통념과의 충돌 / 교차 해석 / SK 맥락에서의 의미 /
     남은 쟁점)은 기획서 6.4를 "다뤄야 할 요소"로 참고하되, 순서·소제목·분리
     방식은 주제에 맞게 재구성한다. 같은 골격을 반복하지 않는다
   - **근거 claim 주석 규칙** (⑤ 검증이 이 형식만 인식한다 — 형식이 틀리면 근거 없는 문단으로 잡힌다)
     · 문단 **바로 다음 줄**에 `<!-- claims: ID1, ID2 -->` 한 줄로 단다. ID는 쉼표로 구분.
     · 근거를 쓴 문단은 **빠짐없이** 단다 — 수치·비율이나 "~에 따르면", "연구 결과" 같은
       인용 표현이 있는데 주석이 없으면 검증 리포트가 "근거 주석 누락 의심"으로 지목한다.
     · 세 줄 요약도 본문 주장을 요약하므로 근거가 되는 claim ID를 단다.
     · evidence 파일에 없는 ID나 출처는 쓰지 않는다 — 검증에서 실패 처리된다.
     · 제언의 처방 값(2주·주 1회)과 서지 연도(2026년)는 근거 수치가 아니므로 검사 면제.
       검증기는 제언형 문단도 액션 마커로 인식해 기간·횟수를 "처방 값"으로 분류한다 —
       면제받자고 소제목에 "액션" 같은 라벨을 붙일 필요는 없다.
   - 내부 자료 사용 시 api_eligible=1 문서만 사용
⑤ 검증 → content/drafts/{slug}-verification.md
   - **실사용 기준(A2)**: `python src/verify_article.py content/drafts/{slug}.md` 실행.
     evidence 파일 전체가 아니라 **본문이 실제 인용한 claim**(문단 뒤 `<!-- claims: ... -->`)
     만으로 강제 조건을 재계산한다 — 독립 출처 3곳+ / 상반 stance(optimistic·cautious 각 1건+) /
     단일 출처 40% 이하 / 수치는 사용 claim의 metric·text와 대조.
     · evidence에 없는 claim ID나 출처를 본문이 인용하면 **실패**하고 해당 문장을 지목한다.
     · 참고자료는 실사용 문서만 남긴다 — 리포트 4장의 목록을 본문에 반영.
     · 리포트 1장의 "문장 ↔ claim ID 대응"으로 사람이 근거를 따라 읽을 수 있다.
     · 제언 문단의 처방 값(2주·주 1회)과 달력 연도(2026년)는 수치 검사에서 면제.
       리포트 4장은 본문 직접 인용을 내부 자료 원문과 대조한다 — 문구 일치까지가 기계
       검증이고, 발언 맥락 왜곡 여부는 발행 전 사람 확인 항목이다.
   - 이어서 banned_phrases 검사, eval/rubric.md 8항목 자체 채점
   - 검증 실패(exit 1)거나 18점 미만이면 ④ 재실행 (최대 2회)
