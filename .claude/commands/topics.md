이번 주 토픽 후보를 발굴해 표로 제시한다 (파이프라인 ③단계): $ARGUMENTS

$ARGUMENTS는 선택 인자다. `--as-of YYYY-MM-DD`(기준일 변경)·`--top N`(후보 수) 등
`src/topics/discover.py`의 옵션을 그대로 넘긴다. 비어 있으면 오늘 기준 후보 3개.

## 1단계 — 신호 산출 (스크립트)

```
python src/topics/discover.py --json $ARGUMENTS
```

이 단계는 전부 결정적이다. 사람·모델의 판단이 들어가지 않는다.

- 시간 창은 **published_at 기준** 최근 14일 / 급증도 비교는 직전 28일.
  수집 시각(collected_at)은 쓰지 않는다 — 소급 수집분이 신호를 오염시키기 때문.
- 급증도는 창 전체 claim 대비 **비중** 비다. 일별 유입량이 아직 정상 상태가 아니라
  건수 배수는 부풀어 보인다(참고용으로 `raw_daily_ratio`에 함께 담긴다).
- 자격 조건 4가지를 모두 채운 묶음만 후보가 된다:
  독립 출처 4곳+ · 상반 stance(optimistic·cautious) 실존 · 연결 이론 카드 2장+ ·
  T1·T2 claim 2건+ (T5 단독 근거 금지 — 기획서 4.1).
  출처·stance·T1·T2는 **증거로 쓸 수 있는 claim만** 센다 (요약뿐 문서에서 나온
  `from_summary=1` claim은 신호 집계에는 들어가지만 자격 계산에서는 빠진다).
- OpenAI·Anthropic 키가 필요 없다. 이미 저장된 claim 임베딩만 쓴다.
- SQLite 모드면 "건너뜀"을 출력하고 정상 종료한다 — 그 경우 여기서 멈추고 보고한다.

## 2단계 — 주제 한 줄과 예상 앵글 (판단)

1단계 페이로드의 후보마다 `sample_claims`와 `theory_cards`를 읽고 두 줄을 쓴다.

- **주제(한 줄)**: 묶음이 무엇에 관한 것인지 한 문장. 리더 claim을 그대로 옮기지 말고
  묶음 전체를 아우르는 말로 다시 쓴다. 제목이 아니라 주제 진술이다.
- **예상 앵글(한 줄)**: "이 재료로 쓴다면 어떤 논지가 가능한가"의 밑그림.
  반증 조건까지 갖춘 정식 앵글은 ⑤-1(`/draft`)의 몫이므로 여기서는 한 줄까지만 쓴다.
  이론 카드가 현상의 **경계 조건**과 부딪히는 각도를 우선 본다 (기획서 3.5).

규칙:
- `sample_claims`에 있는 사실만 쓴다. 없는 수치·출처를 지어내지 않는다 (절대 규칙 3).
- claim 문장을 그대로 복사하지 않는다 (절대 규칙 1).
- 재료가 무엇을 말하는지 확신이 서지 않으면 앵글 칸에 "재료 확인 필요"라고 적는다.
  억지로 만들지 않는다 (절대 규칙 2의 정신).

## 3단계 — 보고서 저장

```
python src/topics/discover.py $ARGUMENTS
```

`content/topics/YYYY-WW.md`가 만들어진다. 2단계에서 쓴 주제·앵글 두 칸을 표와 상세 절에
채워 넣고 저장한다 (스크립트는 그 자리를 `_(/topics 2단계 기입)_`으로 비워 둔다).

## 4단계 — 보고

사용자에게 후보 표를 그대로 보여 주고, 다음 한 줄을 덧붙인다:

- 후보가 3개 미만이면 **부족 사유**(보고서의 "후보 부족" 절)를 함께 전한다.
  자격 미달은 실패가 아니라 정상 결과다 — 억지 후보를 만들지 않는다.
- 선택은 사람이 한다. 고른 토픽으로 `/draft <slug>` 를 이어서 실행한다.
