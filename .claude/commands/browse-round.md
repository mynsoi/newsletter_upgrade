# /browse-round — 월간 브라우저 라운드 (목록 순회 + 격상 + 유료 건별 보조)

한 달에 한 번, 브라우저 보조 수집 전체를 순서대로 수행한다. 개별 소스 절차는
`/browse-collect`(browse-collect.md)를 그대로 따른다 — 이 커맨드는 순서·보고·마무리만 담당.

## ① 사전 점검

1. 시작 시각을 기록한다 (보고서의 소요 시간 기준).
2. Chrome(Claude in Chrome) 연결과 자동 다운로드 허용 상태를 확인한다 — 연결이 안 되거나
   다운로드가 차단돼 있으면 **멈추고** 사용자에게 안내한다(주소창 차단 아이콘 → 항상 허용).
   인앱 브라우저만 필요한 소스(BCG·Deloitte 등 공개 사이트)는 Chrome 없이도 진행 가능하나,
   ③·④(격상·유료 건별)는 Chrome이 전제다.

## ② 목록 소스 순회

sources.yaml에서 **type: browse + browse_mode: list**이고 **라운드 제외가 아닌** 소스를
순서대로 수행한다 (제외 여부는 note 확인 — 예: 삼정KPMG "라운드 제외, 분기 1회 사람 확인").

- 각 소스를 `/browse-collect <소스ID>` 목록 모드 절차로 수행한다
  (건수 규칙·PDF 쌍 처리·선택자 실측 포함).
- **소스 하나가 끝날 때마다 중간 보고**: "소스명: 신규 N · 격상 M · 실패 K"

## ③ McKinsey 격상

1. DB에서 `source_id='mckinsey-insights' AND summary_only=1`이고 **최근 30일** 발행분의
   제목·URL 목록을 조회해 사용자에게 제시한다.
2. **사용자가 고른 것만** 같은 URL을 브라우저(실제 Chrome — 인앱은 봇 차단)로 추출해
   등재한다 → 격상(본문 교체·summary_only 0·추출 대기 복귀).

## ④ 유료 건별 보조 (HBR Korea · DBR)

1. 각 홈을 열어 **지난 한 달 글의 제목·URL 목록만** 확인해 제시한다 —
   **본문은 열지 않는다** (건별 선별 보조일 뿐, 목록 순회 수집이 아니다).
2. **사용자가 고른 URL만** `/browse-collect` 건별 모드로 수집한다
   (로그인 확인 → license_note 기록 → 유료 잘림 검사).

## ⑤ 마무리

1. `content/reports/browse-round-YYYY-MM.md` 생성:
   - 소스별 신규·격상·중복·실패 표
   - 발견 적합 건수 vs 수집 건수
   - 소요 시간(시작~종료), 총 유입 건수
   - 특이사항(선택자 변경·차단·구조 변화 등)
2. **무유입 경보 대상이 해소됐는지 확인**한다 (inflow-alert 이슈의 browse 소스가
   이번 라운드로 유입됐는지 — 해소됐으면 이슈에 코멘트/닫기).
3. sources.yaml에 선택자·note 변경이 있으면 `make sources-doc` 재생성.
4. 보고서·변경분 커밋·push 후 **"다음 라운드는 한 달 뒤"** 를 안내한다.

## ⑥ 중단 규칙

사용자가 "여기까지"라고 하면 그 시점까지의 결과로 ⑤(보고서·커밋·안내)를 수행한다.
미처리 소스는 보고서에 "미수행"으로 명시한다.
