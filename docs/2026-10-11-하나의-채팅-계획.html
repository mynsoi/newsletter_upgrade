하나의 채팅 계획

입력창의 제목 · 피드백 · 진행자 구분을 없앱니다. 그냥 말하듯 보내면 Claude가 지금 글의 단계와 대화를 보고 할 일 하나를 고르고 짧게 답합니다. 실행은 지금 있는 버튼 동작 그대로 서버가 합니다. 버튼도 그대로 둡니다 — 눌러도 되고 말해도 됩니다.

1. 지금 질문에 대한 답

  • 지금은 안 됩니다. 진행자는 예전 지시문(옛 위키 명령, 본문 그림 3개)이라 대화 화면·원문 다시 고르기를 모릅니다.
  • "주제 다시"는 두 가지라 나눠서 처리합니다.
    • 같은 주제로 원문만 다시 고르기 — 쓰기 전이면 바로. 쓴 뒤라면 "처음부터 다시 쓴 뒤 다시 고를까요?"라고 되묻고 실행.
    • 말할 것 자체를 바꾸기 — 새 대화를 열고 대화에 그 대화로 가는 카드를 띄움. 지금 대화는 그대로 둠.
    • 주제 지도에서 온 글(원문 고르기 기록이 없음)은 원문 바꿔 끼우기만, 다시 고르기는 새 대화로.

3. 지킬 것

  • 멘토 말은 받은 그대로 넘깁니다. 판단은 할 일만 고르고 말을 다듬지 않습니다 — 피드백·제목 요청·원문 다시 고르기 모두 보낸 말 전체를 그대로.
  • 제목과 본문은 Claude가 짓지 않습니다(제목은 astra만). 답하기에서도 제목 예시를 내지 않습니다.
  • 애매하면 실행하지 않고 되묻습니다.
  • 판단하는 Claude는 읽기 전용, 답만(셸 권한 없음). 실행은 서버가 정해진 동작으로만.
  • 삭제는 채팅으로 하지 않습니다(버튼만). 작업이 도는 동안엔 답하기만 받고, 실행은 "끝난 뒤에"라고 답합니다.
  • 답과 판단은 대화에 남습니다(멘토 말 → 짧은 답 → 결과 카드). 결과 카드가 없는 답은 보낸 순간의 자리에 붙습니다.

4. 정해 주실 것 기본값으로 진행해도 됩니다

A. 진행자기본: 화면에서 없앰. 지금 진행자는 셸 권한으로 명령을 직접 돌리는 Claude라, 하나의 채팅이 대신하면 필요 없어짐. 다른 길: 숨은 비상구로 남기고 지시문만 지금 흐름으로 고침.
B. 되묻고 실행할 동작기본: 처음부터 다시 쓰기 · 확정은 한 번 되묻고, 쓰기는 바로.

5. 순서와 확인

  1. 판단 먼저 시험 — 저장소에 남은 멘토의 실제 말(피드백·제목 요청·요청·이어서 한 말, 휴지통 것은 읽기만)마다 그때의 단계와 실제로 원했던 동작을 붙여 정답표를 만들고, 판단기를 돌려 맞은 비율·틀린 줄·응답 시간을 HTML로 보여 드림. 피드백인데 제목으로 간 것, 질문인데 실행한 것은 따로 셈. 이 결과를 보고 화면에 붙일지 정함(판단 모델도 이때 잰 값으로 제안).
  2. 서버 say 동작 하나 — 판단(답만) → 기존 동작 실행 → 대화 기록
  3. 화면 — 입력창의 모드 드롭다운 없앰, AI 답 말풍선, 되묻기 버튼(예/아니오)
