# 칼럼 발행 작업실 시연 영상 — 제작 계획 (3차)

작성 2026-10-26 · 대상 브랜치 `mentor-lab-integration` · 상태: **확정 (10/26)** — 리허설 → 녹화 진행

## 0. 이 영상이 할 일

- **쓰임: 멘토링 과제 발표 영상.** 심사위원에게 우리가 만든 칼럼 발행 작업실의 기능과 결과물을 보여 주고 설득한다.
- **보여 줄 것:** 작업실을 원문 수집부터 발행까지 한 단계씩 실제로 조작하며, 단계마다 무엇이 일어나고 어떤 기능이 있는지 보여 준다. 마지막에 실제 발행된 웹 칼럼과 메일을 보여 준다.
- **심사위원이 가져가야 할 세 가지**
  1. **사람은 판단만 한다.** 원문 찾기·주제 정리·쓰기·고쳐 쓰기·그림·발행은 AI와 작업실이 하고, 사람은 고르고 피드백한다.
  2. **근거가 있는 글이다.** 모든 글이 실제 원문 사례에서 출발하고, 원문 전체를 읽고 확인하며, 원문에 없는 숫자는 확정 전에 걸러진다.
  3. **실제로 나간다.** 버튼 몇 번으로 웹 칼럼과 사내 메일이 만들어지고, 이미 여러 편을 발행했다.
- **톤:** 기업이 업체에 맡겨 만든 제품 소개 영상. 차분한 AI 내레이션, 낮은 BGM, 자막, 확대·강조·콜아웃. 사용법 팁은 넣지 않는다.
- **길이:** 본편 약 7분 30초. 요약본은 만들지 않는다(10/26).
- **결정된 것 (10/26):** AI 음성 내레이션 · AI 이름(Claude·astra·gti)을 그대로 보여 줌 · 실제로 발행한 뒤 촬영이 끝나면 내림.

## 1. 도구 — 리서치 요약

### 1-1. 녹화: 스크립트 자동 녹화 (Playwright)
- 저장소에 작업실을 브라우저로 조작하는 코드가 이미 있다(`docs/readme/capture.py`, `wiki-eval/ui_e2e.py --full`). 이를 바탕으로 장면별 녹화 스크립트를 만든다.
- 장점: 다시 찍어도 똑같고, 타이핑 속도와 마우스 동선이 매끈하다. 클릭 시각과 좌표를 기록해 두면 편집에서 바로 확대 지점으로 쓴다.
- Playwright는 실제 커서를 찍지 않으므로 페이지에 가짜 커서와 클릭 물결을 그려 넣는다(DemoForge 같은 공개 도구도 같은 방식).
- 예비안: 사람이 직접 찍고 자동으로 확대해 주는 툴 — Windows용 FocuSee, AutoZoom, Tella. Screen Studio는 맥 전용.

### 1-2. 단계별 도구

| 단계 | 쓸 도구 | 메모 |
|---|---|---|
| 녹화 | Playwright + ffmpeg(webm→mp4) | 장면 하나 = 파일 하나 |
| 내레이션 | 타입캐스트 또는 클로바더빙 | 같은 문장 3개로 목소리 2~3개를 비교해 고름 |
| 자막 | Vrew | 음성 인식 자막 → 오탈자 손보기 |
| 편집(컷·확대·강조) | DaVinci Resolve(무료) 또는 CapCut | — |
| 제목 카드·도식 애니메이션·숫자 카드 | Remotion(코드로 만드는 영상) | Claude가 작성, 수정이 쉬움 |
| 배경음악 | YouTube 오디오 라이브러리 등 사용권이 분명한 것 | 내레이션 아래 -20dB 정도 |

녹화부터 대본·AI 음성·확대까지 다 해 주는 올인원 서비스(Clueso, Trainn 등)는 한국어 품질과 사내 화면을 외부에 올리는 문제 때문에 쓰지 않는다.

## 2. 제작 순서

| 단계 | 할 일 | 기간 |
|---|---|---|
| 1. 계획 확정 | 이 문서 확정 | — |
| 2. 리허설 | 시연 요청 문장 후보 2~3개를 실제로 돌려 보고, 글 옵션·추천 원문·수치 점검이 화면에 잘 보이는 문장을 고른다 | 0.5일 |
| 3. 화면·데이터 준비 | 아래 2-1 | 0.5일 |
| 4. 녹화 스크립트 | `docs/demo/record.py` — 장면별 녹화, 클릭 기록 `marks.json` | 0.5일 |
| 5. 녹화 | 장면별로. AI가 처리하는 동안도 끊지 않고 찍는다(편집에서 빨리 감기) | 0.5~1일 |
| 6. 내레이션 | 장면마다 음성 파일 하나 | 0.5일 |
| 7. 편집 | 아래 2-2 | 1~1.5일 |
| 8. 검수·내보내기 | 민감 정보, 자막 오탈자, 1080p mp4(H.264) | 0.5일 |

### 2-1. 화면·데이터 준비
- **화면:** 브라우저 1920×1080, 확대 125%(영상에서 글씨가 읽히게), 북마크바·알림 끔. 다크/라이트 중 하나로 통일.
- **시연 글:** 리허설에서 고른 요청 문장으로 새 대화를 시작한다. 첨부 문서는 사내 수치가 없는 것으로.
- **공유 끄기:** 촬영 시간에는 동업자에게 다른 PC 작업을 멈춰 달라고 한다(90초마다 받아 오는 변경이 화면에 끼어들 수 있음).
- **실제 발행 후 내리기:**
  1. 동업자에게 촬영 시각과 "시연 글이 잠깐 아카이브에 올라갔다 내려간다"를 알린다.
  2. 받는 사람·참조는 본인 메일만.
  3. 촬영이 끝나면 `py -3 -X utf8 -I scripts/publish.py unpublish <글>` → 아카이브 목록에서 빠졌는지 확인.
  4. 시연 글의 확정본·발행 커밋을 남길지 지울지 정한다.
- **가릴 것:** 받는 사람 메일 주소, 사내 자료의 미공개 수치, 원문 본문의 긴 노출(저작권), API 키·로컬 경로.

### 2-2. 편집 원칙 — 제품 소개 영상처럼
1. **컷:** 장면 사이 군더더기를 지운다. AI가 처리하는 구간은 8~16배로 빨리 감고 모서리에 "실제 약 N분"을 띄운다.
2. **확대:** 버튼을 누르기 직전에 1.5~2배로 부드럽게 당기고, 결과가 뜨면 전체로 돌아온다. 한 장면에 1~2번만.
3. **강조:** 설명하는 곳만 밝게 남기고 나머지는 살짝 어둡게.
4. **콜아웃:** 버튼 옆 짧은 라벨(예: "원문을 끝까지 읽고 확인").
5. **AI 배지:** 화면 오른쪽 아래에 지금 일하는 AI(Claude / astra / gti / aside).
6. **챕터 카드:** 장면 사이 1.5초 "03 · 글 옵션".
7. **숫자 카드:** 원문 수·주제 수·발행 편수처럼 규모를 보여 주는 숫자는 애니메이션 카드로.
8. **분할 화면:** 웹 칼럼과 메일을 나란히.

### 2-3. 내레이션 표기 (AI 음성용)
- 영어 이름은 읽는 대로 적는다: astra → "아스트라", gti → "지티아이", Claude → "클로드", Supabase → "수파베이스", aside → "어사이드", Outlook → "아웃룩". 자막에는 원래 표기.
- 숫자도 읽는 대로: "1,000자" → "천 자", "1,769편" → "천칠백육십구 편".
- 한 문장 40자 안팎, 1분에 250~300자.

### 1. 한눈에 보기 (0:00–0:35)
- 🎥 2초 제목 카드 "칼럼 발행 작업실" → 작업실 메인 화면.
- 🎙 (첫 문장) "사내 뉴스레터 칼럼을 원문 수집부터 발행까지 한 화면에서 만드는 칼럼 발행 작업실입니다."
- 🎥 흐름도 애니메이션: 서재 → 주제 지도 → 요청 → 글 옵션 → 원문 확인 → 쓰기 → 피드백 → 원고·제목 → 그림 → 확정 → 발행. 사람이 하는 칸만 빨갛게 하나씩 켜진다.
- 🎥 AI 배지 넷이 역할과 함께 나타남: Claude — 초안·주제 거르기·사내 자료 추천 / astra — 원문 카드·글 옵션·원문 확인·재작성·제목·그림 설명 / gti — 그림 / aside — 원문 수집.
- 🎙 "빨간 칸만 사람이 합니다. 무엇을 쓸지 말하고, 고르고, 피드백하고, 발행합니다. 나머지는 역할을 나눈 AI 넷이 맡습니다."
- ⭐ 사람은 판단만, 작업은 AI가.

### 2. 서재 — 원문 모으기 (1:10–1:45)
- 🎥 왼쪽 메뉴 **서재** → 탭 전체 · 컨설팅 · 저널·매체 · 기업 자료 · 연구기관을 차례로 → 원문 카드 하나.
- 🎥 **Supabase 받기**에 마우스를 올려 마지막 받은 시각 툴팁 → **aside · 소스** 수집 로그 ⏩.
- 🤖 aside
- 💬 숫자 카드: "소스 29곳 · 원문 1,769편"(촬영 시점 수치로 갱신)
- 🎙 "서재에는 컨설팅사와 경영 저널, 기업 리포트, 연구기관의 글이 원문 그대로 쌓입니다. 여섯 시간마다 저절로 새 글을 받고, RSS로 받을 수 없는 사이트는 어사이드 브라우저가 직접 열어 가져옵니다. 요약이 아니라 원문 전체를 저장하는 이유는, 요약으로 쓰면 원문의 맥락과 말맛이 빠지기 때문입니다."
- ⭐ 글감이 자동으로, 원문 그대로 모인다.

### 3. 주제 지도 — 쓸 만한 주제 거르기 (1:45–2:30)
- 🎥 **주제 지도** → 4단계 도식 오버레이(원문 카드 → 묶기 → 거르기 → 제목 후보) → 탭 **쓸 만함 · 보통 · 뺌 · 쓴 글**.
- 🎥 카드 하나 펼치기: 이 글이 말할 것, 왜 쓸모 있는지, 대상 독자, 중심·받침·반례 원문.
- 🔍 "왜 쓸모 있는지" 한 줄 → 원문 목록.
- 🎥 판정을 보통 → 쓸 만함으로 바꾸는 장면 → **다시 거르기** 강조.
- 🤖 astra → Claude → astra
- 💬 숫자 카드: "주제 126개"
- 🎙 "모은 원문은 네 단계를 거쳐 주제 지도가 됩니다. 아스트라가 원문마다 있었던 일과 글쓴이의 주장을 카드로 만들고, 주장이 같은 원문끼리 묶습니다. 클로드는 이 주제가 우리 회사 구성원에게 쓸모 있는지 거릅니다. 사람이 판정을 바꾸면 그 판정이 예시로 쌓여, 다음 거르기가 사람의 기준을 따라갑니다."
- ⭐ 사람의 판단을 학습하는 주제 거르기.

### 4. 요청과 글 옵션 (2:30–3:30)
- 🎥 **메인** → 빈 채팅 "어떤 글을 쓸까요?" + 추천 주제 넷 → **다른 추천**.
- 🎥 입력창에 한 글자씩 시연 요청 문장(리허설에서 정함) → 클립 버튼으로 문서 첨부 → 보내기.
- 🎥 "원문 카드 보는 중 → 카드 보고 글 옵션 짜는 중" ⏩(💬 "실제 약 1~2분") → 글 옵션 카드 3~5개.
- 🤖 astra
- 🔍 옵션 하나: **이 글이 말할 것** 한 문장 + 원문 2~3편(서로 다른 발행처).
- 🎥 채팅으로 이어서 말하기(예: "다른 회사 사례로 다시") → 앞 차례가 접히고 새 옵션 ⏩ → 하나 골라 **이 글로**.
- 🎙 "글은 대화로 시작합니다. 추천 주제를 고르거나, 하고 싶은 말을 그냥 적으면 됩니다. 사내 문서를 올리면 함께 참고합니다. 작업실은 천 편이 넘는 원문에서 후보를 좁힌 뒤, 아스트라가 글 옵션을 몇 가지 냅니다. 옵션마다 이 글이 무슨 말을 할지 한 문장과, 그 말을 보여 줄 실제 사례가 붙어 있습니다. 쓰기 전에 방향부터 고르는 겁니다."
- ⭐ 쓰기 전에 메시지를 먼저 정한다 — 뜬구름 잡는 글을 막는 장치.

### 5. 원문 확인 (3:30–4:10)
- 🎥 "원문 끝까지 읽고 확인 · 추천 고르는 중" ⏩ → 고른 원문: **중심** · **받침** 칩, **확인에서 뺀 원문**(이유와 함께), **추천 원문**.
- 🎥 추천 원문 **넣기** → "추천 원문 끝까지 읽는 중" ⏩ → 들어감. 사내 자료 대목 추천이 뜨면 함께 보여 줌.
- 🤖 astra · Claude(사내 자료)
- 🔍 확인에서 뺀 원문과 그 이유.
- 🎥 **이 원문으로**.
- 🎙 "옵션을 고르면 고른 원문을 처음부터 끝까지 읽고, 카드에서 기대한 내용이 원문에 정말 있는지 확인합니다. 글을 받치지 못하는 원문은 이유와 함께 뺍니다. 더 넣을 만한 원문과 사내 자료도 추천하고, 넣을 때도 끝까지 읽고 확인합니다."
- ⭐ 요약이 아니라 원문 전체로 검증한다.

### 6. 쓰기와 피드백 (4:10–5:40)
- 🎥 쓰기 카드의 대상 독자 칩 → 독자 선택(전 직원 · 임원급 · 팀장급 · 시니어급 · 주니어급) → **쓰기**(버튼 입자 효과에 확대).
- 🎥 과정 카드가 차례로 ⏩, 카드가 생기는 순간만 정속: "과정 1 · Claude 초안" → "과정 2 · astra 재작성" → "과정 3 · 기준 반영". 카드마다 글자 수.
