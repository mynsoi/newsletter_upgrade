심사위원이 가져갈 세 가지(1차와 같은 뼈대, 셋째를 바꿈)
1. **사람은 판단만 한다** — 주제를 고르거나 말하고, 피드백하고, 발행 버튼을 누른다.
2. **근거가 있는 글이다** — 원문 전체로 확인하고, 원문에 없는 숫자는 확정 전에 걸러진다.
3. **쓸수록 나아진다** — 사람이 준 문체 피드백이 규칙(스킬)으로 쌓여 다음 글에 처음부터 반영된다.

### 1. 오프닝 (0:00–0:20)
- 🎥 제목 카드 "AI 뉴스레터 칼럼 제작 자동화 · 시연" → **프로젝트 소개 보고 2페이지의 구조도**([2026-10-29-프로젝트-소개-보고.html](2026-10-29-프로젝트-소개-보고.html), archify)를 애니메이션으로:
  1. 아래 줄(자동·AI)이 왼쪽부터 켜짐 — 소스 41곳 → 수집/claim 추출 → 칼럼 재료 받기(서재) → 카드/주제 묶기(주제 지도) → 대화로 글쓰기 → 수치 검증/그림 → 발행. 구간 머리말 **모으기·자동 / 쓰기·AI+사람 / 마무리**.
  2. 위 줄 빨간 칸 셋이 차례로 켜짐 — **주제 고르기**(추천에서 고르거나 직접 적기) · **피드백**(받은 그대로 다음 과정) · **확정**(그림·과정을 골라 확정).
  3. 피드백 → 글쓰기로 돌아오는 점선을 강조하고 "그리고 규칙으로" 꼬리표를 하나 더 그린다(5장 예고).
- 🎙 "AI 뉴스레터 칼럼 제작 자동화 시연입니다. 원문 수집과 주제 정리는 자동으로, 쓰기는 AI가 합니다. 사람이 하는 일은 세 가지, 주제를 고르고, 피드백하고, 확정하는 것입니다."
- 🤖 Claude · astra · gti · aside 배지 넷이 아래 줄 칸 옆에 붙음(수집 aside, 묶기·쓰기 Claude·astra, 그림 gti).
- 숫자는 구조도와 맞춘다: 소스 41곳 · 원문 2,056편 · 137주제(촬영 날 다시 확인).

### 2. 화면 둘러보기 — 메뉴·탭 (0:20–1:15)
- 🎥 왼쪽 메뉴 아이콘 넷에 차례로 마우스 → 라벨 콜아웃 **서재 · 주제 · 글 · 발행**, 로고 = 메인(채팅).
- 🎥 **서재** → 탭 전체 · 컨설팅 · 저널·매체 · 기업 자료 · 연구기관을 1초씩 → 원문 하나 열어 전문 → **Supabase 받기**에 마우스(마지막 받은 시각).
- 🎙 "왼쪽 메뉴는 서재, 주제, 글, 발행 넷입니다. 서재에는 컨설팅사, 경영 저널, 기업 자료, 연구기관의 글 이천여 편이 원문 그대로 쌓입니다. 여섯 시간마다 새 글을 받고, 바로 받고 싶으면 수파베이스 받기를 누릅니다."
- 🎥 **주제** → 탭 **쓸 만함 · 보통 · 뺌 · 쓴 글** → 카드 하나 펼침(이 글이 말할 것, 중심·받침 원문) → 판정 칩·**이 주제로** 버튼 콜아웃.
- 🎙 "주제에서는 같은 주장을 하는 원문끼리 묶은 주제 카드를 봅니다. 클로드가 쓸 만함, 보통, 뺌으로 거르고, 사람이 판정을 바꾸면 그 판정이 다음 거르기의 기준이 됩니다."
- 🎥 **글** 목록(쓰는 중·확정) → **발행** 목록 1초씩.
- 🎙 "글에는 쓰는 중인 글과 확정한 글이, 발행에는 웹과 메일로 나갈 글이 모입니다."
- 💬 숫자 카드: "원문 1,8xx편 · 주제 1xx개"(촬영 날 수치)
- ⭐ 한 화면 안에 수집부터 발행까지 있다.

### 3. 글쓰기 A — 추천 주제로 (1:15–2:05)
- 🎥 로고 → 메인 "어떤 글을 쓸까요?" + 추천 주제 카드 4개(대상 독자 칩) → **다른 추천** → 다음 4개 → 하나 클릭("여는 중").
- 🎙 "글은 메인 화면의 채팅에서 시작합니다. 첫 번째 방법은 추천 주제입니다. 주제 지도에서 쓸 만하다고 거른 주제 가운데 아직 쓰지 않은 것이 네 개씩 뜨고, 다른 추천을 누르면 다음 네 개가 나옵니다."
- 🎥 **주제 지도에서 고른 주제** 카드(사람 판정 이유 · 중심 1 · 받침 2, 대상 독자 자동) → 곧바로 "원문 끝까지 읽고 확인 · 추천 고르는 중" ⏩(💬 "실제 약 1~2분") → **고른 원문**("뺀 원문 없음", 원문마다 '가져올 사실') + **사내 맥락 넣음**(자동) + 추천 원문 4 🔍.
- 🤖 astra · Claude(사내 맥락)
- 🎙 "주제를 누르면 글 옵션 없이 그 주제의 원문으로 바로 들어갑니다. 원문을 끝까지 읽고 확인하고, 맞는 사내 자료도 함께 넣습니다."
- 🎥 **이 원문으로 본문 쓰기** → 쓰기 카드(대상 독자 칩) → **쓰기** → 과정 카드 1·2·3 ⏩(💬 "실제 약 2분 30초") — 카드마다 글자 수와 "수치 N개 원문 확인".
- 🤖 Claude → astra → astra
- 🎙 "쓰기를 누르면 클로드가 초안을 쓰고, 아스트라가 다시 쓰고, 글쓰기 규칙을 반영합니다. 과정마다 결과가 남아, 비교 탭에서 바뀐 문장을 볼 수 있습니다."
- 🎥 과정 2 → 오른쪽 '지금 글' **비교** 탭(바뀐 문장 형광) 🔍.
- ⭐ 무엇을 쓸지 몰라도 클릭 한 번으로 근거 확인까지 간다.

**리허설 결과 (11/3)** — 추천 첫 카드 "자료를 많이 가진 회사라도 그 자료가 업무에서 무슨 뜻인지 연결하지 못하면 AI는 일을 맡기 어렵다"(팀장급)로 돌림.
- 화면 순서: 카드 클릭 → 주제 카드 → **원문 확인이 자동으로 바로 시작**(글 옵션 단계 없음) → 고른 원문 3편(MIT Technology Review · McKinsey · 플렉스) + 사내 맥락(이천포럼 회장 발언) 자동으로 넣음 + 추천 원문 4편 → '이 원문으로 본문 쓰기' → '쓰기'(버튼 두 번).
- 시간: 원문 확인 약 2분, 쓰기 약 2분 30초(과정 1 Claude 1,027자 · 과정 2 astra 931자 · 과정 3 astra 806자). 과정 카드에 "수치 6개 원문 확인"이 바로 보임.
- 그래서 바꾼 것: 원문 확인과 사내 맥락은 **3장에서 보여 주고**, 4장 B는 글 옵션에 집중한다(아래).
- 촬영 때 고를 주제: 이 주제 또는 같은 줄의 다른 추천(시험 글은 지웠으므로 다시 추천에 뜸).

### 4. 글쓰기 B — 직접 주제를 정해서 (2:05–3:00)
- 🎥 새 대화 → 입력창에 한 글자씩 요청 문장 → 클립으로 사내 문서 첨부 → 보내기 → "카드 보고 글 옵션 짜는 중" ⏩ → 글 옵션 4~5개.
- 🤖 astra
- 🎙 "두 번째 방법은 하고 싶은 이야기를 직접 적는 것입니다. 사내 문서를 함께 올릴 수도 있습니다. 아스트라가 원문에서 글 옵션을 냅니다. 옵션마다 이 글이 말할 한 문장과 실제 사례가 붙어 있어, 쓰기 전에 메시지부터 고릅니다."
- 🎥 **이 글로** → 원문 확인 ⏩(3장에서 본 장면이라 2초) → **확인에서 뺀 원문**(이유)이 있으면 🔍, 추천 원문 **넣기** 한 번 → **쓰기** → 과정 1·2·3 ⏩(한 화면으로 압축).
- 🤖 astra
- 🎙 "옵션을 고르면 똑같이 원문을 끝까지 확인하고, 받치지 못하는 원문은 이유와 함께 뺍니다. 그다음 쓰기는 첫 번째 방법과 같습니다."
- ⭐ 쓰기 전에 메시지와 근거부터 확인한다.
- 요청 문장: 1차 리허설에서 고른 ③ "회사가 AI를 쓰라고 하는데 정작 배울 시간이나 지원은 없어서 답답하다는 이야기를 써 보고 싶어"를 그대로 쓰는 안(옵션·추천 원문·사내 맥락이 잘 나왔음). 첨부 문서는 1차와 같은 것.

### 5. ★ 피드백이 규칙이 된다 (3:00–4:25)
**이번 영상의 핵심 장면. 확대·강조를 가장 많이 쓴다.**

- 🎥 B의 과정 3 → 입력창에 **문체 피드백** 입력(아래 후보) → 보내기 → 과정 4 ⏩ → 비교 탭에서 고친 문장 🔍. 짚지 않은 문단이 바뀌었으면 '짚지 않은 문단 N곳 바뀜' 표시도.
- 🤖 astra
- 🎙 "다 쓴 글에 고칠 점을 적으면 아스트라가 짚은 곳만 고쳐 다음 과정을 만듭니다."
- 🎥 원고 정하기 → 제목 4개 중 하나 → 그림(머리 그림·본문 그림) ⏩ 3초 → 확정 카드 점검 줄("수치 N개 · 모두 고른 원문에 있음") 🔍 → **확정**. (1차보다 크게 압축 — 각 1~2초)
- 🤖 astra → gti
- 🎙 "원고와 제목, 그림을 정하고 확정합니다. 확정 전에는 글의 숫자가 모두 원문에 있는지 자동으로 점검합니다."
- 🎥 확정 직후 "이 글의 피드백에서 규칙 후보 찾는 중" → 확정 카드 아래 **규칙 후보** 카드. 후보마다 종류(새 규칙 / 이 글만 / 이미 있음).
- 🤖 astra
- 💬 콜아웃: "피드백 → 글쓰기 규칙(스킬)"
- 🎙 "여기서 새로 더한 기능입니다. 확정할 때 아스트라가 이 글에서 받은 피드백을 모아, 다음 글에도 쓸 만한 것을 글쓰기 규칙 후보로 올립니다."
- 🎥 새 규칙 후보 하나 펼침 → 근거: **받은 피드백** + **글에서 바뀐 문장(전 → 후)** 🔍.
- 🎙 "후보마다 어떤 피드백에서 나왔는지, 글에서 어떤 문장이 바뀌었는지가 함께 보입니다. 이 글에만 해당하는 요청은 따로 표시합니다."
- 🎥 **규칙에 넣기** → "규칙에 넣음 · 이름 · 시각" → 화면 전환: `briefs/글쓰기규칙.md`의 해당 묶음 끝에 한 줄이 더해진 모습(형광) → 다음 글의 과정 3 카드에 이 규칙이 쓰인 모습.
- 🎙 "규칙에 넣으면 글쓰기 규칙 파일에 한 줄이 더해지고, 다음 글부터 초안과 재작성이 이 규칙을 읽습니다."
- 💬 숫자 카드: "피드백을 규칙으로 올린 뒤 같은 글을 다시 쓰자 — 지적 7건 중 5건이 처음부터 나오지 않음"(11/2 검증, f53c582)
- 🎙 "지난 피드백을 규칙으로 바꾼 뒤 같은 글을 다시 써 보니, 짚었던 지적 일곱 건 중 다섯 건이 처음부터 나오지 않았습니다."
- ⭐ 사람의 문체 피드백이 버려지지 않고 스킬로 쌓여, 쓸수록 손이 덜 간다.

**문체 피드백 후보** (지금 규칙 11개와 겹치지 않는 것 — 리허설에서 '새 규칙'으로 잡히는 걸 고름)
- ① "'~할 수 있습니다', '~일지도 모릅니다' 같은 흐린 끝맺음을 줄이고 단정해서 써 줘"
- ② "영어 용어는 처음 나올 때 우리말 풀이를 괄호로 붙여 줘"
- ③ (대조용) "둘째 문단 사례를 한 문장 줄여 줘" — '이 글만'으로 분류되는지 보여 주는 용도. 넣을지 리허설 뒤 판단.

### 6. 발행·엔딩 (4:25–5:00)

- 🎙 "확정한 글은 웹과 메일 모양을 미리 보고, 버튼 두 번으로 발행합니다."
