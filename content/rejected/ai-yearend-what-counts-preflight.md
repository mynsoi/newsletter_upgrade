## 1. 내부 자료 메타데이터 확인

운영 DB `internal_docs`를 읽기 전용 트랜잭션으로 조회했다. 내부 문서 본문은 조회하지 않았다. 메타데이터 조회 전 본문을 생성 프롬프트에 넣지 않았다.

두 문서 모두 API 허용 게이트는 통과했다. 다만 현재 등록 정책은 등급 미운용이며, 색인 코드가 A·1을 고정 기록한다. DB 값을 별도의 보안 심사 결과로 확대 해석하지 않는다. 안내 문서 날짜는 내부 등록목록상 발행일 미상으로 등록 기한(5/15)을 대신 쓴 값이다. 향후 본문에서 정확한 발행일로 단정하지 않는다. 내부 자료 사용 시 ‘우리’ 시점 간접 서술과 2026년 시점 표시를 적용한다.

## 2. 묶음6의 실사용 가능성

원래 토픽 문서는 6건이라고 집계하지만 ID는 대표 5건만 제공한다. 5건은 모두 운영 DB에 존재하고 `from_summary=0`이다. 빠진 ms-worklab 1건은 출처·stance·주장 내용이 일치하는 아래 후보로 복원했다. 원래 군집의 전체 ID 목록을 확보한 것은 아니므로 **원래 6번째 ID 확정으로 보지 않는다.** 이 후보를 포함해도 통과하지 못한다.

판정 기준은 단순 검색 적중이 아니라, 해당 claim 자체가 이번 글의 AI 활용·성과·평가·보상 논지를 뒷받침하는지, 원문의 맥락을 보존하는지, 개인과 조직의 분석 단위를 혼동하지 않는지다. ‘제외’는 연구 자체의 가치나 진위를 부정하는 뜻이 아니다.

WorkLab 검색에서는 `1A06A213BEB9E8B2C086A0EA3FF`도 나왔다. 이는 적응 압박과 기존 목표에 집중하는 편이 안전하다는 인식으로, 토픽 설명의 ‘보상’ 대목과 직접 일치하지 않아 원래 6번째 후보로 선택하지 않았다. 추가 증거로 합산하지 않는다.

**결론: 내용상 생존 후보 최대 2건·2출처. 요청 티어를 엄격히 적용하면 1건·1출처.** 어느 기준에서도 3건에 못 미친다. from_summary 때문에 탈락한 것은 아니며, 주제 관련성·외적 타당도·티어 범위가 문제다. 토픽 단계의 T1·T2 4건 가운데 사내 맥락에 실사용 가능한 것은 현재 T2 1건뿐이다.

## 4. 중단 범위와 재개 조건

사용자의 ‘3건 미만이면 멈추고 알려줘’ 지시에 따라 여기서 중단한다. 다른 묶음의 증거나 이론으로 부족분을 자동 보충하지 않았다.

- 미실행: 실무 T2·T3 검색, 연구 T1·T2 검색, 검수된 이론 카드 수집, 통합 evidence 작성, 앵글 3안, 세그먼트 매핑, 코어·레이어 집필, 본문 검증.
- 이 파일은 사전 점검 리포트이며 완성 원고의 검증 리포트가 아니다. 원고가 없으므로 verify_article.py와 루브릭 채점을 실행하지 않았다.
- 재개하려면 묶음6만으로 착수하는 조건을 바꾸고, 슬롯1 묶음1·3과 슬롯2에서 실무·연구 근거를 보강할지 사용자가 결정해야 한다.
- 재개 후에도 from_summary=1 제외, 독립 출처 3곳 이상, 낙관·신중 양쪽 근거, T1·T2 2건 이상을 확인한다. 원고의 단일 출처 의존도는 실제 인용한 고유 claim 기준 40% 이하로 검증한다.
- 앵글 3안이 성립하면 선택을 기다린다. 선택 전 매핑이나 집필을 하지 않는다.
- 최종 집필은 config/settings.yaml의 `write_model: claude-opus-5`와 실제 실행 모델이 일치하는 세션에서 수행해야 한다. 현재 Codex 세션을 Opus 5로 간주하지 않는다.
