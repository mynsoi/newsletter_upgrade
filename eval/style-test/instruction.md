# 문체 테스트 — 고정 생성 지시문

`prompts/article_style.md`가 실제로 문체를 잡아 주는지 보려고, **같은 재료·같은 지시문으로
초안을 5회 생성**해 서로 비교한다. 지시문이 회차마다 달라지면 비교가 성립하지 않으므로
아래 블록은 **고치지 않는다.** 지침을 바꾸고 싶으면 `prompts/article_style.md`를 고친다.

회차마다 `{N}`만 1~5로 바꿔 그대로 붙여 넣는다.

---

## 지시문 (회차마다 이 블록만 사용)

```
content/evidence/ai-productivity-paradox.json을 재료로 draft ④(초안 작성)만 수행.
article_style.md와 작성 규칙(claims 주석 포함) 전부 준수. 기존 발행본·이전 테스트
초안은 열지 않는다. 산출: content/drafts/style-test-{N}.md, 머리말에 모델명·생성일·
base 커밋 해시(`git rev-parse --short HEAD`) 기록. 저장 후 verify_article.py 실행해
통과 여부만 기록(실패해도 재생성 금지 — 실패 자체가 비교 데이터). 본문을 다듬거나
재출력하지 않는다.
```

---

## 실행 전 확인 — base를 맞춘다

**모든 회차를 같은 커밋에서 딴 워크트리로 실행한다.** 회차마다 base가 다르면 각 회차가
서로 다른 판본의 `prompts/article_style.md`를 보게 되어, 글의 차이가 모델 차이인지
지침 차이인지 구분할 수 없다.

```
git rev-parse --short HEAD      # 이 값을 초안 머리말에 적는다
```

머리말에 base 해시를 남기는 이유는 나중에 회차 간 base가 어긋났는지 한눈에 대조하기
위해서다. 5회의 해시가 전부 같아야 비교가 성립한다.

> **2026-09-08 기록**: 첫 시도의 회차 1·2를 폐기했다. 회차 2가 `main` 기반 워크트리에서
> 실행돼 통합 전 `article_style.md`(112행)를 보고 쓰였고, 회차 1은 통합 후(228행)를
> 봤다. 두 글의 차이가 모델에서 온 것인지 지침 판본에서 온 것인지 가를 수 없어 비교를
> 버렸다. base 해시 기록은 그 재발을 막으려고 추가한 항목이다.
> (폐기한 초안은 `claude/style-test-instruction-1264f5`·`-e6b4b4` 브랜치에 남아 있다.)

## 이 설계에서 지켜야 할 것

- **재생성 금지.** 검증에 실패해도 다시 만들지 않는다. 실패율과 실패 유형이 이 테스트가
  얻으려는 데이터다. 통과한 초안만 모으면 지침의 효과를 과대평가하게 된다.
- **비교 오염 금지.** 기존 발행본(`content/published/ai-productivity-paradox.md`)과 앞
  회차의 `style-test-*.md`를 열지 않는다. 열면 그쪽 문장을 따라가서 회차가 독립이 아니게 된다.
- **사후 수정 금지.** 저장한 본문을 다듬지 않고, 대화창에 다시 출력하지도 않는다.
  파일에 남은 그대로가 측정 대상이다.
- 회차 산출물은 `content/drafts/style-test-{N}.md`에 남기고 지우지 않는다.
- **base 해시가 회차마다 다르면 그 회차는 버린다.** 지침 판본이 섞인 비교는 쓸 수 없다.
